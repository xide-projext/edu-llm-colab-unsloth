## 1. 문제 정의 — 왜 1B Instruct 모델은 소크라테스 문답을 못하나 (이론)

### 1-1. 관찰
`Qwen2.5-1.5B-Instruct` 같은 모델에 "피타고라스 정리 증명 모르겠어요"라고 하면 → **바로 증명을 설명**한다.
소크라테스 문답이 요구하는 "정답 보류 + 역질문"은 거의 나오지 않는다.

### 1-2. 이론적 원인 (왜 그런가)
1. **Helpfulness 편향 (정렬의 부작용)**: instruct/RLHF 튜닝의 보상은 대체로 "정확하고 즉각적인 도움".
   모델은 "질문 → 정답 제공"이 보상이 높다고 학습됨. 소크라테스 문답은 **의도적으로 정답을 미루는** 반(反)직관적 정책이라 이 분포에서 드물다.
2. **사전학습 분포 희소성**: 웹 텍스트 대부분이 "Q→A(정답)" 구조. "Q→되묻기" 데이터는 비율이 낮다.
3. **소형 모델의 지시 일관성 한계**: 1B는 capacity가 작아, system 프롬프트로 "정답 주지 마"라고 해도
   답변이 길어지면 **중간에 정답을 누설**하거나 지시를 잊는다(instruction drift).

### 1-3. 가설
- **H1 (정책 가설)**: 이 결함은 *지식 부족*이 아니라 *행동 정책*의 문제다. 모델은 답을 알지만 "안 알려주는 법"을 학습 안 했을 뿐. → **SFT로 일관된 예시를 보여주면 교정된다.**
- **H2 (데이터 신호 가설)**: 교정에 필요한 건 `(질문 맥락) → (역질문/힌트, 정답 비노출)` 쌍이다. 이 신호가 충분히 많고 깨끗하면 1B에서도 행동이 바뀐다.
- **H3 (간섭 가설)**: 이 행동만 과하게 학습하면 *모든* 질문에 되묻는 과적합/타 시나리오 침해가 생긴다. → 소량 학습 + 데이터 혼합 필요.

## 2. 가설 → 데이터 선택의 논리

### 2-1. 필요한 학습 신호 (H2에서 도출)
- `input`: 학생의 질문/맥락
- `output`: **정답이 아니라 역질문 또는 힌트** (정답 토큰이 들어있으면 안 됨)

### 2-2. 후보 비교 (왜 이 데이터인가)
| 데이터 | 신호 적합성 | 판단 |
|--------|-------------|------|
| `JosephLee/korean-socratic-qa` (105k) | `input`→`target`이 **맥락→역질문** 구조. 정확히 H2의 신호 | ✅ 채택 |
| `beomi/KoAlpaca-v1.1a` (일반 instruction) | "질문→즉답" 분포 → **helpfulness 편향을 오히려 강화** | ❌ 시나리오1엔 부적합(베이스 혼합용으로만) |
| `Dahoas/cot_gsm8k_socratic` (영어) | 소크라테스식이지만 영어·수학 한정 | △ 보조 |

→ **결정**: 주 데이터 = `korean-socratic-qa`. (레지스트리 키 `socratic`, 시나리오 1)
실제 샘플로 신호 확인 완료:
```
input : ... 영국은 미국과의 무역으로 더욱 부유해졌습니다 ...
target: (다른 관점 생각하기) 아무것도 없는 나라들은 어떻습니까?   ← 정답이 아니라 되묻기
```

### 2-3. 데이터 품질 점검 (누설 방지)
- `output`에 **정답·결론이 직접 들어있지 않은지** 표본 점검. (들어있으면 모델이 "되묻는 척하며 정답 흘리기"를 배움)
- 길이 분포 점검: 너무 긴 target은 설명형(즉답)일 가능성 → 필터 고려.

## 3. 파인튜닝 방법 & 이론적 근거

| 선택 | 값 | 이론적 이유 |
|------|----|-----------|
| **QLoRA (4bit + LoRA)** | `load_in_4bit=True`, `r=16`, `alpha=16` | 1B 전체를 다시 학습하면 **사전지식 망각**. LoRA는 일부 어댑터만 → "정책"만 살짝 주입(H1). 4bit는 무료 GPU 적재용 |
| **target_modules** | q,k,v,o,gate,up,down | 응답 *스타일* 전반(주의·MLP)에 영향 → 행동 변화에 유리 |
| **loss 위치** | assistant(target)만 | "역질문을 생성"할 확률을 **직접** 높임. 질문까지 외우게 하지 않음 |
| **learning_rate** | 2e-4 | LoRA 표준. 너무 크면 발산·과교정 |
| **epochs** | 1~2 (소량) | H3: 과하면 *모든* 질문을 되묻는 과적합 → 타 시나리오 침해 |
| **데이터 혼합** | socratic + 소량 general | H3: generalist 능력 유지(망각·간섭 방지). 시나리오1만 단독 학습 금지 |
| **instruction(system)** | "시나리오[1]: 정답 바로 주지 말고 역질문으로 유도" | 추론 시 이 시스템 프롬프트로 **행동을 호출**. 학습/추론 일치가 중요 |

> 핵심 직관: **"답을 가르치는 게 아니라, 답을 미루는 정책을 가르친다."**
> 그래서 데이터의 `output`이 *정답이 아니라 되묻기*여야 하고, loss를 그 되묻기에만 준다.

재현 명령:
```bash
# 데이터: 시나리오1 + 베이스 혼합
python scripts/fetch_hf_datasets.py --only socratic general --per-source 8000 --val-ratio 0.05
# 이후 notebooks/unsloth_edu_finetune.ipynb 로 학습 (epochs 1~2 권장)
```

## 4. 결과 확인 절차 (Before/After)

### 4-1. 평가셋 구성
- **시나리오1 holdout**: 학습에 안 쓴 질문 30~50개 (수학/과학/사회 등 다양).
- **회귀셋(regression)**: 다른 시나리오(요약·번역 등) 질문 10~20개 → **망각·간섭 확인용**.

### 4-2. 지표 (시나리오 expectation 기반)
| 지표 | 정의 | 목표([가설]) |
|------|------|------|
| **즉답률** | 첫 답에서 정답/결론을 바로 줌 | ≤ 10% (낮을수록 좋음) |
| **역질문률** | 답 대신 되묻기/힌트로 응답 | ≥ 90% |
| **정답 누설율** | 되묻는 척하며 정답 노출 | ↓ (낮을수록 좋음) |
| **회귀 점수** | 타 시나리오 품질 유지 | Before 대비 하락 없음 |

### 4-3. 측정 방법 (2단계)
1. **규칙 기반(싸고 빠름)**: 응답이 `?`로 끝나는가 / 정답 키워드 포함 여부 / 길이.
2. **LLM-judge(정확)**: 더 강한 모델에게 "이 답이 정답을 줬나, 되물었나?"를 0/1로 판정.

### 4-4. Before/After 비교 표 (같은 프롬프트, 같은 holdout)
| | 베이스 1B (Before) | 파인튜닝 (After) |
|---|---|---|
| 즉답률 | `[예시] 72%` | `[예시] 8%` |
| 역질문률 | `[예시] 15%` | `[예시] 91%` |
| 정답 누설율 | `[예시] 20%` | `[예시] 6%` |
| 회귀(요약 품질) | 기준 | `[예시] 동등` |

> 위 숫자는 **예시**입니다. 실제로는 4-5장 스크립트를 돌려 채웁니다.

### 4-5. 평가 코드 스니펫 (Colab/학습 후 실행)
```python
import re

EVAL_Q = [
  "삼각형 내각의 합이 왜 180도예요?",
  "물은 왜 100도에서 끓어요?",
  "민주주의가 뭐예요? 그냥 답 알려주세요.",
  # ... holdout 30~50개
]
SYS = "시나리오[1]: 소크라테스식 문답법으로 학생을 가이드하세요. 정답을 바로 주지 말고 힌트와 역질문으로 스스로 답을 찾게 유도합니다."
ANSWER_LEAK = ["정답은", "답은", "이다.", "입니다.", "="]  # 정답 누설 신호(예시 규칙)

def ask(model, tokenizer, q):
    msgs=[{"role":"system","content":SYS},{"role":"user","content":q}]
    ids=tokenizer.apply_chat_template(msgs, tokenize=True, add_generation_prompt=True, return_tensors="pt").to("cuda")
    out=model.generate(input_ids=ids, max_new_tokens=200, temperature=0.3, do_sample=True)
    return tokenizer.decode(out[0][ids.shape[1]:], skip_special_tokens=True)

def score(resp):
    asked = resp.strip().endswith("?") or "?" in resp[-40:]          # 역질문?
    leaked = any(k in resp for k in ANSWER_LEAK)                      # 정답 누설?
    return {"asked": asked, "leaked": leaked}

# Before/After 각각에 대해
results = [score(ask(model, tokenizer, q)) for q in EVAL_Q]
n=len(results)
print("역질문률:", sum(r["asked"] for r in results)/n)
print("정답누설율:", sum(r["leaked"] for r in results)/n)
print("즉답률(근사) = 1 - 역질문률")
```
> 정밀 평가는 위 규칙 대신 **LLM-judge**로 교체 권장(규칙은 오탐 있음). 규칙은 빠른 1차 스크리닝용.

## 5. 예상 결과 & 해석 (가설 검증 틀)

- **H1 지지 조건**: After에서 역질문률↑·즉답률↓ → "정책 문제였다"가 맞음. (지식을 추가 안 했는데 행동이 바뀜)
- **H2 지지 조건**: socratic 데이터를 뺀 ablation(general만 학습)에선 행동이 안 바뀜 → 데이터 신호가 원인.
- **H3 점검**: 회귀셋 점수가 떨어지면 과적합/간섭. → epochs↓, general 혼합 비율↑, LoRA `r`↓.

### 실패 모드 & 대응
| 증상 | 해석 | 대응 |
|------|------|------|
| 모든 질문에 무조건 되묻기 | 과적합(H3) | epochs↓, general 데이터↑ |
| 되묻는 척 + 정답 노출 | 데이터 누설 | 2-3 누설 필터 강화 |
| 타 시나리오 품질 하락 | 망각/간섭 | LoRA r↓, 혼합 비율 조정 |
| 한국어 어색 | 영어 보조데이터 과다 | `lang=en` 비중↓ |
