# 🧭 파인튜닝 방법 선택 사고법 — "방법보다 가설이 먼저"

> Unsloth는 여러 파인튜닝 방법(SFT·LoRA/QLoRA·FFT·CPT·DPO/ORPO/KTO·GRPO/RL·Vision/TTS·Embedding)을 제공한다.
> **무엇을 고를지(answer)보다, 왜 그것이 맞는지(hypothesis)를 먼저 생각하는 습관**이 핵심이다.
> 이 문서는 "생각을 먼저 하게 만드는" 사고 틀과, 그 사고를 **가르치는 방법**을 함께 정리한다.

관련 문서: 사례(논문) [`CASE_STUDY_scenario1_socratic.md`](CASE_STUDY_scenario1_socratic.md) · 노브 [`LEARNING.md`](LEARNING.md) · 시나리오 [`SCENARIO_GUIDE.md`](SCENARIO_GUIDE.md)

---

## 0. 핵심 원칙 (한 문장)

> **"무엇이 부족한가(결함의 종류)"를 먼저 정의하면, 방법은 거기서 따라 나온다.**
> 방법을 먼저 고르면, 문제에 방법을 억지로 맞추게 된다(안티패턴).**

방법은 각각 **암묵적 가정**을 깔고 있다. 그 가정이 내 문제와 맞을 때만 그 방법이 옳다.
그래서 순서는 항상: **결함 관찰 → 결함 유형 가설 → 필요한 학습 신호 → 방법 → 기각 조건 → 검증.**

---

## 1. 첫 질문: "무엇이 부족한가?" (결함 유형 분류)

방법을 떠올리기 전에, 모델이 못하는 것이 **어떤 종류의 부족**인지 분류한다.

| 결함 유형 | 증상 | 필요한 학습 신호 | → 1차 후보 방법 |
|-----------|------|------------------|------------------|
| **정책/행동(policy)** | 답은 아는데 *방식*이 틀림 (즉답·말투·형식) | (입력 → 모범 응답) 쌍 | **SFT (LoRA/QLoRA)** |
| **지식/도메인(knowledge)** | *내용 자체*를 모름 (신규 분야·언어·용어) | 대량 도메인 **원문 코퍼스** | **Continued Pretraining (CPT)** |
| **선호/미세정렬(preference)** | 둘 다 그럴듯, *더 나은 쪽*을 못 고름 (공손함·안전성·톤) | (선택됨 vs 거부됨) **쌍 비교** | **DPO / ORPO / KTO** |
| **검증가능 능력(verifiable skill)** | 정답 여부를 *자동 채점* 가능 (수학·코드·형식준수) | **보상 함수**(정답=보상) | **RL: GRPO / GSPO** |
| **포맷/구조(format)** | 내용은 OK, *출력 틀*만 어긋남 (JSON·표) | 소량의 형식 예시 | **SFT 소량** |
| **멀티모달/음성** | 이미지·오디오 입출력 필요 | 모달별 쌍 데이터 | **Vision / TTS FT** |
| **검색·유사도** | 임베딩 품질 | 쌍/삼중항 | **Embedding FT** |

> 시나리오 1(소크라테스 문답)은 *정책* 결함 → **SFT(QLoRA)**. 이 분류가 사례 보고서의 출발점이었다.

## 2. Unsloth 방법별 이론 카드 (가정 · 언제 · 위험)

각 방법을 "암묵적 가정 / 언제 / 신호 형태 / 비용 / 위험"으로 본다.

### 2.1 SFT (Supervised Fine-Tuning)
- **가정**: 원하는 행동을 *모범 답안 쌍*으로 보여주면 모방한다. (행동은 모사 가능)
- **언제**: 정책·스타일·형식·과제 수행을 가르칠 때 (가장 흔한 출발점).
- **신호**: `(input → output)` 쌍. loss는 output에만.
- **위험**: 데이터에 없는 일반화 약함, 과적합 시 망각.

### 2.2 LoRA vs QLoRA vs FFT (SFT의 *적용 범위*)
- **QLoRA(4-bit)**: 본체 동결 + 4bit + 저랭크 어댑터. **권장 출발점**(메모리 ~75%↓, 정확도 대부분 회복).
- **LoRA(16-bit)**: 양자화 없이 어댑터 학습. VRAM 여유 있고 마지막 정확도가 중요할 때.
- **FFT(전체 미세조정)**: 모든 가중치 수정. 자원 큼, **대개 불필요** — 연구상 LoRA가 제대로면 FFT에 필적. **먼저 LoRA/QLoRA로 검증 후** 정말 필요할 때만.
- **사고 포인트**: "전체를 바꿔야 하나, 일부만 바꿔도 되나?" 행동/정책은 보통 일부(LoRA)로 충분.

### 2.3 Continued Pretraining (CPT)
- **가정**: 부족한 건 *행동이 아니라 내용/언어* → 대량 원문에 추가 사전학습.
- **언제**: 신규 언어·전문 도메인 지식 주입. (예: 특정 법령·의료 코퍼스)
- **신호**: 라벨 없는 **원문 텍스트**(QA 쌍 아님).
- **위험**: 비용 큼, 기존 능력 망각 → 보통 이후 SFT로 정렬.

### 2.4 선호 최적화 (DPO / ORPO / KTO)
- **가정**: "더 나은 답"을 *쌍 비교*로 알려주면 그 방향으로 이동(보상모델 없이).
- **언제**: SFT 후 *미세한 선호*(공손·안전·간결) 다듬기. 정답이 하나로 안 정해질 때.
- **신호**: `(chosen, rejected)` 쌍 (KTO는 단일 라벨도 가능).
- **위험**: 좋은 쌍 데이터 필요, SFT 없이 단독은 보통 비효율.

### 2.5 강화학습 (GRPO / GSPO)
- **가정**: 정답을 *자동 채점(보상)* 할 수 있으면, 모델이 스스로 탐색해 능력을 끌어올린다.
- **언제**: 수학·코드·형식준수처럼 **검증 가능한** 능력, 추론 강화.
- **신호**: 라벨 쌍이 아니라 **보상 함수**(정답=+, 오답=−).
- **위험**: 설계·비용·불안정성 큼. 보상 정의 불가하면 부적합.

### 2.6 Vision / TTS / Embedding FT
- **Vision**: 이미지+텍스트 멀티모달(FastVisionModel). 예: 도표 읽기.
- **TTS**: 음성 합성 미세조정.
- **Embedding**: 검색·유사도용 임베딩 품질.
- **가정**: 입출력 *모달리티 자체*가 다름 → 해당 모달 데이터 필요.

## 3. 생각을 먼저 하게 만드는 도구 — "가설 카드 (Hypothesis Card)"

방법을 고르기 전에 **반드시 이 카드를 먼저 채운다.** (강제 장치 = forcing function)

```
[가설 카드]
1) 관찰된 결함:        (예) 1B가 질문 받으면 정답을 바로 줌
2) 결함 유형 가설:     □정책 □지식 □선호 □검증가능능력 □포맷 □멀티모달
                       → (예) 정책(행동) 문제. 답은 알지만 보류 정책 미학습
3) 그렇게 본 근거:     (예) instruct의 helpfulness 편향, 지식은 충분
4) 필요한 학습 신호:   (예) (맥락 → 역질문, 정답 비노출) 쌍
5) 1차 후보 방법:      (예) SFT(QLoRA), r=16, output-only loss
6) 왜 다른 방법은 아닌가: (예) CPT=지식문제 아님 / DPO=쌍데이터 없음 / RL=보상정의 불가
7) 기각 조건(반증):    (예) general만 학습해도 개선되면 H2 기각
8) 검증 지표:          (예) IAR↓, SQR↑, ALR↓, 회귀 없음
```

> 핵심은 **6·7번**이다. "왜 다른 방법이 아닌지"와 "무엇이 보이면 내 가설이 틀린지"를 적게 하면,
> 방법을 *답으로 외우는* 대신 *추론*하게 된다.

## 4. 의사결정 플로우 (문제 → 방법)

```
모델이 무엇을 못하나?
        │
        ▼
내용/언어 자체를 모르나? ──예──► Continued Pretraining (+이후 SFT)
        │아니오
        ▼
정답을 자동 채점할 수 있나(수학/코드/형식)? ──예──► RL: GRPO/GSPO
        │아니오
        ▼
"더 나은 답"을 쌍으로 줄 수 있나(공손/안전/톤)? ──예──► DPO/ORPO/KTO (SFT 후)
        │아니오
        ▼
원하는 행동의 모범 답안 쌍이 있나? ──예──► SFT
                                          └ VRAM? → QLoRA(기본) → 필요시 LoRA → 정말 필요할 때만 FFT
        │아니오(데이터 없음)
        ▼
데이터부터 확보 (검색/구성) ── SCENARIO_GUIDE.md 절차
```

## 5. 대조 예시 (같은 사고법, 다른 결론)

| 문제 | 결함 유형 | 왜 그 방법인가 | 방법 |
|------|-----------|----------------|------|
| 소크라테스 문답을 못함 | 정책 | 답은 알지만 보류 정책 미학습 | **SFT/QLoRA** |
| 한국 특정 법령을 모름 | 지식 | 내용 자체 부재 → 모범답으로 안 됨, 원문 필요 | **CPT** → SFT |
| 두 답 중 더 공손한 걸 못 고름 | 선호 | 정답이 하나 아님, 우열만 존재 | **DPO/ORPO** |
| 수학 정답률이 낮음 | 검증가능 능력 | 정답 자동 채점 가능 → 보상학습 | **GRPO** |
| 항상 JSON으로 답하게 | 포맷 | 내용 OK, 틀만 교정 | **SFT 소량** |

> 같은 *질문 절차*를 거치는데 결론(방법)이 달라진다 — 이게 "사고법"의 핵심이다.

## 6. 이 사고를 *가르치는* 방법 (Pedagogy)

학습자가 방법을 외우는 대신 **스스로 추론하도록** 만드는 5가지 장치:

1. **항상 "무엇이 부족한가?"부터** — 방법 이름을 입에 올리기 전에 결함 유형을 말하게 한다.
2. **가설 카드 의무화** — §3 카드를 안 채우면 학습 시작 금지. *왜 다른 방법이 아닌지(6번)* 와 *반증 조건(7번)* 을 반드시 적게.
3. **방법이 아니라 가정을 묻기** — "이 방법은 무엇을 가정하나? 내 문제가 그 가정을 만족하나?"
4. **반증으로 검증** — ablation/baseline으로 *인과* 를 확인(예: general만 학습 = H2 반증 테스트). 좋아 보인다고 끝내지 않는다.
5. **소크라테스식으로 가르치기(자기참조)** — 정답 대신 "그럼 지식 문제일까 행동 문제일까?"라고 되묻는다.
   (우리 시나리오 1의 교수법을, 가르치는 사람도 그대로 적용)

### 연습 과제 (Exercise)
새 시나리오 하나를 받아, **방법을 말하기 전에 가설 카드부터** 작성 → 후보 방법과 *기각된 방법의 이유* 를 발표 → ablation 설계까지. 채점 기준은 "방법이 맞았나"가 아니라 **"추론이 타당했나(6·7번)"**.

## 7. 안티패턴 (이러면 생각을 건너뛴 것)

- ❌ **방법부터 고른다**: "LoRA로 하자" → 무엇이 부족한지 정의 안 함.
- ❌ **FFT 남용**: 검증 없이 전체 미세조정부터. (먼저 QLoRA로 검증)
- ❌ **데이터 없는 RL**: 보상 정의 불가한데 GRPO 시도.
- ❌ **지식 문제에 SFT**: 내용 부재인데 QA 쌍 몇 개로 해결하려 함(→ CPT 필요).
- ❌ **반증 조건 없음**: "좋아 보인다"로 종료, ablation 없음.
- ❌ **선호를 SFT로**: 우열만 있는 문제를 단일 정답 SFT로 강제.
